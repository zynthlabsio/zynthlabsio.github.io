From messy pages to clean data: a checklist that actually works

Data extraction · 17 November 2026

Data extraction looks simple until the spreadsheet arrives: names split across two columns, prices mixed with currency symbols, duplicates everywhere. None of that is a scraping problem. It is a specification problem — and this checklist fixes it before the work starts.

Define every field, with an example

List each column you want and give one real example row. “Price” is ambiguous; “price_usd = 129.00, numbers only, no currency symbol” is not. Examples settle questions that descriptions leave open.

Agree the output format up front

CSV, XLSX or JSON? One sheet or several? What should an empty field look like — blank, or an explicit marker? Deciding this after delivery means reformatting by hand.

Say what counts as a duplicate

Is the same business at two addresses one row or two? Is a repeated listing with a different price a duplicate or an update? Pick the rule — for example, duplicate means the same name and the same URL — and write it in the brief.

Ask for a sample before the full run

Have the first 20–30 rows delivered and checked before the rest is collected. Format mistakes are cheap to fix at row 25 and expensive at row 2,500. This single step prevents most bad deliveries.

Check the sample like a sceptic

  • Open three source pages at random and compare them with the rows.
  • Sort each column — outliers and mixed formats jump out.
  • Count the rows and compare with the expected total.
  • Check dates, prices and phone numbers for consistent formatting.

Keep the source with the data

Always keep a source URL (or document name) column. Data without provenance cannot be verified, refreshed or trusted later — and refreshing a list is far cheaper than rebuilding it.

Extraction itself is mechanical. Clean data is what you get when the thinking happens before the scraping, not after.
